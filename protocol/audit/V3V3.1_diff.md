### v3.1 構造
```
src/
├── core/
│   ├── hub/       → Hub, Accounting, Holdings, ShareClassManager, HubRegistry, HubHandler
│   ├── spoke/     → Spoke, BalanceSheet, PoolEscrow, VaultRegistry
│   ├── messaging/ → Gateway, GasService, MessageLib, MessageProcessor, MessageDispatcher
```

- `spoke/` → `core/spoke/` + `vaults/` に分離
- `common/` → `core/messaging/` + `core/admin/` + `misc/` に分散
- `managers/` カテゴリが新規追加
- `valuations/` カテゴリが新規追加

## 4. Hub コントラクト変更

### 4.1 Hub.sol

**アーキテクチャの根本的変更: IHubRequestManager プラグインシステム**

v3 では Hub がリクエスト処理を直接実行していたが、v3.1 では `IHubRequestManager` インターフェースによるプラグインシステムに変更。

```solidity
// v3: Hub内部で直接処理
function processDepositRequest(poolId, scId, investor, amount) external {
    // ... 直接処理ロジック
}

// v3.1: プラグインに委譲
function executeRequest(poolId, scId, requestId, request) external auth {
    hubHandler.executeRequest(poolId, scId, requestId, request);
}
```

**主な変更点:**
- `processDepositRequest()` / `processRedeemRequest()` → `executeRequest()` に統合
- `processEpoch()` → 削除（BatchRequestManagerに移動）
- リクエスト処理が Hub から分離され、外部マネージャーに委譲
- `IHubRequestManager` インターフェース追加で拡張性向上
- Pool 作成時に `requestManager` パラメータが必須に

### 4.2 ShareClassManager.sol

**82% コード削減: ~860行 → ~155行**

v3 の ShareClassManager はエポック処理ロジック（`executeEpoch()`、`applyEpoch()` など）を含んでいたが、v3.1 ではこれらが全て `BatchRequestManager` に移動。

```solidity
// v3: エポック処理を内蔵
function executeEpoch(poolId, scId, epochId) external returns (...) {
    // 複雑なエポック計算ロジック
}

// v3.1: 純粋なシェアクラスメタデータ管理のみ
function addShareClass(poolId, scId, name, symbol, decimals, salt, hook) external auth {
    // シェアクラス登録のみ
}
```

**削除された機能:**
- `executeEpoch()` / `applyEpoch()` / `cancelEpoch()`
- `requestDeposit()` / `requestRedeem()` / `cancelDepositRequest()` / `cancelRedeemRequest()`
- 全てのエポック計算・NAV管理ロジック
- `approveDeposit()` / `approveRedeem()` メソッド

**残存機能:**
- シェアクラスの登録・メタデータ管理
- トークン（share token）の mint/burn 権限管理
- PoolId とのマッピング管理

### 4.3 Accounting.sol

**主な変更点:**
- `updateHolding()` の引数に `isIncrease` フラグ追加（符号付き演算対応）
- `setHoldingAmount()` 新規メソッド追加（直接設定）
- Pool-scoped な依存関係管理（`poolId` パラメータ追加）
- `updatePool()` → Pool NAV 更新ロジック簡素化

### 4.4 Holdings.sol

**主な変更点:**
- `Holding` 構造体の変更: `pendingDeposit` / `pendingRedeem` フィールド削除
- `updateHolding()` に `isIncrease` bool パラメータ追加
- `setHoldingAmount()` 新規追加
- PoolId スコープのデータ管理に変更

### 4.5 HubHandler.sol（新規: HubHelpers.sol 置換）

```solidity
// v3: HubHelpers.sol - 内部ヘルパー関数群
// v3.1: HubHandler.sol - より構造化されたリクエスト処理

contract HubHandler {
    function executeRequest(poolId, scId, requestId, request) external {
        // Generic Request 処理
    }

    function executeCallback(poolId, scId, requestId, callback) external {
        // Generic Callback 処理
    }
}
```

### 4.6 HubRegistry.sol（新規: PoolRegistry.sol 置換）

**主な変更点:**
- Pool 作成時に `IHubRequestManager` 指定が必須
- `dependency` / `metadata` が Pool スコープに変更（PoolId + key → value）
- Pool の pause/unpause 機能追加
- シェアクラスごとの `hook` 設定管理

## 5. Vault コントラクト変更

### 5.1 BatchRequestManager.sol（新規: 最大の追加 ~977行）

v3 のオフチェーン/パラチェーンで行われていたエポック処理をオンチェーンに移行。

```solidity
contract BatchRequestManager is IHubRequestManager {
    // エポックベースのバッチ処理
    function processEpoch(poolId, scId) external {
        // リクエストの集約・実行
    }

    function applyEpoch(poolId, scId, epochId) external {
        // エポック結果の適用
    }

    // NAV管理
    function updateNAV(poolId, scId, nav) external {
        // 純資産価値更新
    }
}
```

**監査上重要:**
- オフチェーン → オンチェーン移行による信頼モデル変更
- エポック計算の正確性検証が必要
- ガスコストの増加と DoS 耐性

### 5.2 AsyncVault.sol / AsyncRequestManager.sol

**主な変更点:**
- リクエスト型: 14種以上の個別メッセージ → `Generic Request` / `RequestCallback` に統一
- `msg.value` によるガス代支払い（v3 の pool subsidy prepayment モデルから変更）
- `address refund` パラメータ追加（余剰ガス代返金先）
- `RequestMessageLib` / `RequestCallbackMessageLib` で エンコーディング分離

```solidity
// v3: 個別メッセージ型
function requestDeposit(amount, receiver, owner) external {
    gateway.send(MessageLib.DepositRequest(...));
}

// v3.1: 汎用リクエスト型
function requestDeposit(amount, receiver, owner) external payable {
    gateway.send(RequestMessageLib.encode(Request{...}), msg.value);
}
```

### 5.3 VaultRouter.sol

**主な変更点:**
- `withBatch()` コールバックパターン導入（`BatchedMulticall` 統合）
- `msg.value` 分配ロジック追加
- `RefundEscrow` との連携（余剰ガスリファンド）
- `permit` / `permitWithBatch` 系メソッドのリファクタリング
- Wrapped token サポートの追加

### 5.4 RefundEscrow.sol（新規）

```solidity
contract RefundEscrow {
    mapping(address => uint256) public refunds;

    function deposit(address refundee) external payable {
        refunds[refundee] += msg.value;
    }

    function withdraw() external {
        uint256 amount = refunds[msg.sender];
        refunds[msg.sender] = 0;
        payable(msg.sender).transfer(amount);
    }
}
```

v3 の pool subsidy prepayment を置換。ユーザーが `msg.value` でガス代を支払い、余剰分は `RefundEscrow` 経由で返金。

### 5.5 SyncManager.sol（SyncRequestManager 置換）

**主な変更点:**
- 名前変更: `SyncRequestManager` → `SyncManager`
- `IHubRequestManager` インターフェース準拠
- 同期リクエスト処理の簡素化

## 6. Messaging / Gateway 変更

### 6.1 Gateway.sol

**根本的な再設計:**

```solidity
// v3: フラットなメッセージ送受信
function send(bytes message) external {
    adapter.send(message);
}

// v3.1: バッチ対応 + ガス管理統合
function send(bytes message, uint256 gasLimit) external payable {
    // msg.value からガス代支払い
    // バッチモード時はメッセージ蓄積
}

function withBatch(function() callback) external {
    // バッチモード開始
    callback();
    // バッチ内メッセージを一括送信
}
```

**主な変更点:**
- **バッチ送信**: `withBatch()` パターンで複数メッセージを一括送信
- **ガス管理統合**: `msg.value` で直接ガス代支払い（GasService連携強化）
- **メッセージ型削減**: 14種以上 → `Request` / `RequestCallback` + 数種類の管理メッセージ
- **TransientBytesLib**: バッチ中のメッセージをトランジェントストレージに蓄積

### 6.2 GasService.sol

**per-message gas limit システム:**

```solidity
// v3: フラットレートガス
uint256 public gasPrice;

// v3.1: メッセージタイプ別ガス上限（27種類）
mapping(uint8 => uint256) public gasLimits;
```

**主な変更点:**
- 27種類のメッセージタイプ別ガス上限設定
- `estimateGas()` メソッド追加
- `msg.value` ベースの支払いモデル
- プール補助金モデル廃止

### 6.3 MessageLib.sol

**メッセージ型の大幅削減:**

```solidity
// v3 のメッセージ型（14種以上）
DepositRequest, RedeemRequest, CancelDepositRequest, CancelRedeemRequest,
FulfilledDepositRequest, FulfilledRedeemRequest, FulfilledCancelDepositRequest,
FulfilledCancelRedeemRequest, TriggerRedeemRequest, ...

// v3.1 のメッセージ型
Request, RequestCallback,  // 汎用リクエスト（全てのdeposit/redeemを統合）
UpdateContract, UpdateHolding, UpdateSharePrice,  // 管理系
RegisterAsset, NotifyPool,  // 登録系
// ... 計27種類（v3の型を汎用化して削減）
```

### 6.4 MessageProcessor.sol / MessageDispatcher.sol（新規）

Gateway から分離されたメッセージ処理パイプライン:
- `MessageProcessor`: 受信メッセージの解析・ルーティング
- `MessageDispatcher`: 送信メッセージの配信先選択

## 8. Hooks 変更

### 8.1 BaseTransferHook.sol（新規: 基底クラス）

**8つの転送フロー分類:**

```solidity
abstract contract BaseTransferHook {
    enum TransferType {
        Transfer,           // 一般転送
        Mint,              // 新規発行
        Burn,              // 焼却
        DepositFulfill,    // デポジット充足
        RedeemFulfill,     // リデンプション充足
        CancelDeposit,     // デポジットキャンセル
        CancelRedeem,      // リデンプションキャンセル
        CrossChainTransfer // クロスチェーン転送
    }

    function onTransfer(
        address from,
        address to,
        uint256 amount,
        TransferType transferType
    ) external virtual returns (bool);
}
```

v3 では `onTransfer(from, to, amount)` のみだったが、v3.1 では転送の種類を区別して制御可能に。

### 8.2 FreelyTransferable.sol（新規）

全ての転送を無条件で許可するフック。テスト用途。

### 8.3 FreezeOnly.sol / FullRestrictions.sol / RedemptionRestrictions.sol

**主な変更点:**
- `BaseTransferHook` を継承するように変更
- `TransferType` 対応
- 各フックで許可/拒否する転送タイプの定義

## 10. Valuations / Managers（新規）

### 10.1 IValuation API 変更

```solidity
// v3
interface IValuation {
    function getQuote(uint256 amount, address base, address quote)
        external view returns (uint256);
}

// v3.1
interface IValuation {
    function getPrice(PoolId poolId, ShareClassId scId, AssetId assetId)
        external view returns (D18);
    function getQuote(PoolId poolId, ShareClassId scId, AssetId assetId, uint256 amount)
        external view returns (uint256);
}
```

**変更点:**
- Pool-scoped な価格取得に変更
- `getPrice()` 追加（D18 型の価格を直接取得）
- `getQuote()` の引数が Pool/ShareClass/Asset ベースに変更

### 10.2 OracleValuation.sol（新規）

```solidity
contract OracleValuation is IValuation {
    mapping(AssetId => address) public feeders;  // 価格フィーダー
    mapping(AssetId => D18) public prices;       // 最新価格

    function updatePrice(AssetId assetId, D18 price) external onlyFeeder {
        prices[assetId] = price;
    }

    function getPrice(PoolId, ShareClassId, AssetId assetId)
        external view returns (D18) {
        return prices[assetId];
    }
}
```

**監査上重要:** 価格オラクルの操作耐性、フィーダー権限管理

### 10.3 IdentityValuation.sol

v3 から移動（`misc/` → `valuations/`）。1:1 評価（price = 1.0）を返す単純な実装。

### 10.4 Managers（全て新規）
